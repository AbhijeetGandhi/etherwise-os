## 0. The shape of the system (one paragraph)

Stdlib-only Python 3.9 on the Mac mini, SQLite-canonical (`var/etherwise.db`, WAL, 27 migrations), every scheduled job a `runner.run_task(TASK_NAME, fn, module=…)` launched by a `launchd/*.plist`, one `runs` row per invocation, freshness judged by `config.SOURCES` → `core/source_health.py`, model calls only through `core/claude_gateway.py` under `$4/day soft · $8 hard · $80/month` caps, external writes only when `config.SHADOW_MODE[module]` is False (`upwork` and `crm` are live; `chief_of_staff`, `knowledge`, `finance` are shadow). The cockpit is a stdlib `http.server` on `127.0.0.1:5051` reading the DB via `_ro()` (no model calls in-process), seven ES-module tabs registered in `static/js/app.js SECTIONS`, one drill sheet (`drill.js`) behind every figure. Cards come from two producers (the `nudges` engine swept every 2h by `cos_sweep`, and follow-up cards derived live from `drafts.sent_status='pending'`). Guardrails: `.claude/hooks/*` → `core/guardrails.py`; the build-phase marker `.claude/ALLOW_CORE_WRITES` still exists, so `core/`, `.claude/`, `scripts/`, `rails/REGISTRY.md` are writable in agent sessions on the Mac — the manual still says propose diffs for config/whitelists/hooks.

Size: core 4.1k + modules 24.5k + scripts 5.6k lines of Python, tests 22.4k (about 1,477 tests GREEN at the last checkpoint, `tests/test_cockpit.py` alone 292), cockpit JS ~440 KB with `data.py` at 4,350 lines.

## 4. Kernel contracts a new Upwork task must obey

- Entry shape: `TASK_NAME = "upwork_<thing>"` + `main()` → `runner.run_task(TASK_NAME, fn, module="upwork")` (`core/runner.py:218-289`). `module="upwork"` is LIVE (no shadow ledger); an unknown module string is shadow ON. Use the `upwork_` prefix or the task does not get the priority budget.
- `fn(ctx)` returns a metrics dict; raise `runner.TaskSkip("…")` for nothing-new (→ `skipped_empty`, which counts as freshness only if the SOURCES entry sets `empty_ok`); `ctx.anomaly(kind, "warn"|"critical", detail)` to degrade without failing (bind `kind` to the rail's `degrade_kinds`); `ctx.log()` writes `var/logs/YYYY-MM-DD.log` in IST; `ctx.claude(model_key=…)` for model calls, never inside `with db.connect()`.
- Retries re-invoke the whole task on `TransientAPIError`/`ConnectionError`/`TimeoutError` (3 attempts, 30s backoff) — tasks must be idempotent: canonical id as TEXT PK, `SELECT` before `INSERT`, `sync_cursors` upsert for positions, `quarantine` for anything unparseable, never a silent drop.
- Migrations: next is `028_*.sql`; additive, `IF NOT EXISTS`, re-runnable (`db.migrate` has no per-file transaction); after adding one, every task fails loud (`MigrationsPending`) until `PYTHONPATH=. python3 -m core.db` runs on the live DB.
- Registration: `config.SOURCES` entry (`key, label, task_name, max_age_hours, degrade_kinds, critical, backs, launchd_label, catch_up, why`) + `launchd/io.etherwise.v3.<name>.plist` (copy `upwork-mcp-shadow.plist`: Framework Python 3.9, `PYTHONPATH`, logs under `~/Library/Logs/Etherwise-v3/`, `RunAtLoad false`, no `WorkingDirectory`) + `bash launchd/install.sh`. `config.py` is a protected path: write the diff into `var/proposed-diffs/` and ask.
- Terminal statuses never flip: enforced in module code, not the schema (`sync_state.py:29,92-99`); `threads.client_id` never overwritten once set.
- Provenance law in practice: `mcp_shadow_jobs` is its own table so shadow data cannot leak (027 header). Do not co-feed `scored_jobs`, `proposals`, `messages` from two transports; retire the twin in the same change (plist + SOURCES + catch-up).
- Guardrails you will hit on the Mac: `rm` only under `var/`, `/tmp/`; no SQL mutation on any DB but `var/etherwise.db`; any `upwork.com` command with `mutation|sendMessage|submitProposal|-X POST` denied; agent-driven MCP mutations denied while any module is shadow (so an MCP sync must be scheduled code, never an agent tool call); `mcp_client.READ_TOOLS` (`feeds/mcp_client.py:81-86`) refuses non-read verbs before I/O and `tests/test_mcp_transport.py:63-65` pins that every allowlisted name starts with `list_/find_/get_`.
- Restart after edits: launchd processes hold the old code — `bin/cockpit reload` after any cockpit Python change; `launchctl kickstart -k gui/$(id -u)/<label>` for rails.
- Tests: stdlib `unittest`, real temp DB with real migrations, boundaries mocked (never the DB), `mock.patch.dict(config.SHADOW_MODE, {...})`, docstrings citing the incident. Run `PYTHONPATH=. python3 -m unittest tests.test_<x>`; whole suite `discover tests`. Some tests read the Mac-only master reference and `Payroll/employees.json` — they fail anywhere else.
- Checkpoint shape (BUILD_BRIEF house style): headline with date, "Suite N → M GREEN", "Spend for this pass $X", `bin/doctor` PASS/WARN/FAIL, `bin/cockpit reload` done, measured before → after per bullet, "◆ FOR ABHIJEET" for every decision left open, answered items struck through in place.

## 5. Cockpit recipe for the Upwork tab (house style, condensed from `codebase-maps/03_cockpit.md`)

1. **Readers** in `modules/cockpit/data.py`, `_ro()` only, no model calls: `upwork(db_path=None, today=None)` with `today` POSITIONAL (a keyword-only `today`/`now` fails `test_no_routed_reader_exposes_a_clock_slot`), and `upwork_rows(db_path=None, *, stage=None, week=None, frm=None, to=None, _today=None)` validating every param first with `_bad_filter` (200 + `{"error", rows: [], count: 0, total: None}`), returning `{stage, week, rows (≤300), count, total (uncapped COUNT(*))}`. Every figure in `upwork()` must equal one `upwork_rows` query with the same predicate — that parity is what the tests assert (`test_every_funnel_band_equals_its_drill` pattern, `test_cockpit.py:2700-2722`). Never write the literal `/send` in server/data/actions.
2. **Routes**: `GET_ROUTES` (`server.py:33-70`) `"/api/upwork"`, `"/api/upwork/rows"`; any new keyword-only param must be in `QUERY_PARAMS` (`server.py:97-139`, one flat namespace — reuse `stage|week|frm|to|status`).
3. **Section** `static/js/sections/upwork.js`: `export async function render(root, ctx)`; build from `ui.js` (`heading`, `kpi`, `card`, `table`, `notice`, `emptyState`, `fmt.*`, `dash()` — null → "—", 0 → "0" with a note), drills via `openDrill({title, rows, columns, total, time, search, facets, capNote})` from `drill.js`; sections render once (no polling), `r` refreshes; state only in `localStorage.ew_cockpit_upwork_*`.
4. **Register** in `app.js SECTIONS` (`:45-53`) — position = keyboard digit; icon must exist in the `index.html` sprite; `badge: true` + a `refreshBadges` writer only if a "needs me" count belongs in the nav. Tokens only (`tokens.css`), modifiers in `components.css`.

## 6. The card engine seam (condensed from `codebase-maps/04_card_engine.md`)

- Kinds are canonical only if in `config.COS_URGENCY_BASE` (`:919-930`) AND `COS_DECAY_TTL_DAYS` (`:949-960`) (`tests/test_card_kinds.py` pins the pairing); anything else is renamed by `nudges.canonical_kind` at write time (an unknown kind from an unknown source becomes `escalate_client`). Current kinds: commitment_due, hotlead_no_loom, deadline (no producer), owed_reply, escalate_client, lost_pattern, won_no_outcome, system, stale_dossier, capture.
- A rule is a pure function in `chief_of_staff/rules.py` returning `write_nudge` kwargs (`dedup_key`, `kind`, `title`, `payload{evidence_ts, cite|job_url|thread_url}`), appended to `ALL_RULES`; the kind must also be in `sweep.RULE_KINDS` (`sweep.py:41-42`) — that is what makes "condition no longer observed" decay the card automatically (`sweep.py:313-321`). Done on a recurring kind sticks only while `payload.evidence_ts` is not newer than the Done (`nudges.py:368-374`); one-shot kinds in `COS_DONE_TERMINAL_KINDS` are suppressed forever.
- Client-facing kinds (`data._CLIENT_FACING_KINDS`) are hidden with a `card_no_provenance` anomaly unless `detail` carries `thread_url|source|job_url|cite|permalink`. Follow-up keys are per counterparty (`nudges.followup_key`: `followup:c:<client_id>` / `followup:p:<slug>` / `followup:<thread_id>`) and only `followup:` keys are forwarded across re-keying via `card_subjects`; never add a key form without adding it to `nudges.followup_key_forms`.
- Two decision stores: `nudge_state` (cockpit overlay) and `nudges.state` (engine) — `actions.apply_nudge` / `cos_nudge` write both; `data.today()` reads both. Today shows every active nudge except `hotlead_no_loom`; there is no per-tab filter, so an Upwork tab either filters `active_nudges` by `source='upwork'`/key prefix in its own reader or shares Today's queue (law #5 "one screen" decides — question 8.6).
- For the brief's "Needs me now": offers awaiting response → needs `offers` ingestion first (finding 3.2) then `offer:<id>` rule; drafts ready for review → the pending-draft card already IS this, but its clear condition must become reply-observed (finding 3.4); replies owed / stale threads → `owed_reply` rule + `answered_since`; custom-Loom flags → `hotlead_no_loom` exists and is deliberately hidden from Today (`data.py:2096`).
